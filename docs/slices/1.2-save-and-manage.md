# 1.2 — Save something in seconds, and keep it tidy

Status: draft · Milestone: M1 Just me v1 · Security-relevant: no (uses the 1.1 schema; review only if the schema changes)

## Goal

You save a memory by typing just a title, add who it’s for, what it is and when it’s good with single taps, and later change it or let it go, without ever losing what you typed.

## Towards

- Builds **Saving** of the [concept](../concept.md) (§7: what, a note, a link; who it’s for; what kind; when it’s good; more details folded away) and the save page and *Let it go* of the [target design](../design/oh-app.html).
- “Who it’s for” is **names** (*Just me*, *Lena*, *Max*), not spaces: in M3 the app offers “6 ideas with Lena: add them to You & Lena?”.
- Leaves out: links filling themselves in (1.4), sharing into the app (1.5), screenshots and *Needs a look* (1.6), *Remember & plan it* (1.7), gifts *for someone* with an occasion (1.9).

## Design

Board: [1.2-save-and-manage.html](../design/slices/1.2-save-and-manage.html)

- **A** The + opens *Save*: “I’ll hold that thought.” Title (required), a note, a link (optional, kept as typed).
- **B** *Who’s it for?* **Just me** (default) or names you used before, plus *Someone else* (**G**: a first name). Several names are fine; *Just me* clears them.
- *What is it?* kinds (optional, one). *When is it good?* **Any time / Warm days / Cold days / Weekends** (optional; warm and cold exclude each other). For *Events* and *Music*: *From / Until* dates.
- **C** *More details*: needs booking, cost (€ / €€ / €€€), who told you (names), your own tags.
- **D** Errors next to the field: “Give this thought a few words first.”, “That doesn’t look like a link. It should start with https://”. Nothing typed is lost.
- **E** No connection: “Couldn’t save just now. Everything you typed is still here.” + *Try again*. Saving twice by tapping again never creates two memories.
- **F** Saved: back in My memory, the new memory on top, toast “Tucked away. You can let go of that thought now.”
- **H** Edit: the same page (“A little more to remember.”), *Keep these changes*, *Let it go* at the bottom.
- **I** Back with unsaved changes: “Leave without saving?” *Keep writing* / *Leave*.
- **J** *Let it go?* once, then it’s gone: “Let go. Lighter already.”

## Data

No schema change: uses the 1.1 columns. Names for *Who’s it for?* and *Who told you?* come from the caller’s own memories (distinct `who_for` and `told_by`), so there is no people table yet.

## API and app

- Create and update with the new fields (validation as in 1.1); `GET /api/v1/ideas/names` returns the caller’s distinct names (for both chip rows), at most 30, most recent first.
- Double save: the app sends a client-generated key with create and the API returns the existing memory for a repeated key within a short window. Owner decision 2026-10-11 said no duplicate protection, but with phones and flaky networks a double tap creating two memories breaks “saving never fails”. **Needs the owner’s OK** (open question 1).
- Flutter: the save page (shared by create and edit), the name sheet, the unsaved-changes and let-go sheets, the toast, the error banner with retry, the draft kept in memory while the page is open.

## Security and privacy

Owner-only as in 1.1; the names endpoint only reads the caller’s rows. No memory content in logs.

## Done when

1. On your phone you save “Udon bar in Mitte” with just the title in under 5 seconds, and it’s on top of My memory.
2. You save one for Lena, food, cold days, with a link and €€; My memory’s *With someone* shows it, and its page shows everything.
3. With the network off, saving says so and keeps everything; turning it on and *Try again* saves it once.
4. You edit a memory, change who it’s for, and let another one go; leaving with unsaved changes asks first.

## Not now

Filling in from a link (1.4), the share sheet (1.5), screenshots (1.6), planning right after saving (1.7), gift ideas for someone (1.9), voice input.

## Open questions

1. Protect against double saves with a client key (recommended), changing the 2026-10-11 decision?
2. Should *Who’s it for?* stay visible for everyone, or only once a name exists? Proposed: always, with *Just me* selected.
